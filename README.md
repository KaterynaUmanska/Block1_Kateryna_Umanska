# Java Core

Проєкт являє собою консольну багатопотокову програму для потокового парсингу JSON-файлів із записами про закупівлі та формування статистики за вибраним атрибутом у вигляді XML-файлу.

## Предметна область

Предметна область проєкту - облік записів про закупівлю матеріалів.

Основною сутністю є запис про закупівлю (PurchaseRecord). Він містить такі атрибути:

- id (long) - унікальний ідентифікатор запису;
- material (Material) - матеріал, який закуповується;
- quantity (double) - кількість матеріалу;
- status (Status) - статус заявки. Можливі значення: PENDING, APPROVED, PURCHASED, CANCELED.
- tags (String) - текстовий атрибут, який може містити декілька значень, розділених комами.

Другорядною сутністю є матеріал (Material), який описує матеріал, що закуповується, та містить:

- id (long) - ідентифікатор матеріалу;
- name (String) - назву матеріалу;
- unit (Unit) - одиницю вимірювання. Можливі значення: KG, LITERS, METERS, PCS.

Між сутностями існує зв'язок багато-до-одного (Many-to-One):
кожен запис про закупівлю (PurchaseRecord) пов'язаний з одним матеріалом
(Material), при цьому один матеріал може бути пов'язаний з багатьма записами
про закупівлю.

Для формування статистики користувач може вибрати один із таких атрибутів:

- tags - багатозначний текстовий атрибут;
- status - статус запису про закупівлю;
- unit - одиниця вимірювання пов'язаного матеріалу (material.unit);
- material - пов'язаний матеріал (material.name).

Особливістю атрибуту tags є те, що він може містити декілька значень. Наприклад: "metal, heavy".


## Налаштування

Для роботи проєкту необхідно мати встановлену Java 21.

Проєкт містить Maven Wrapper, тому окремо встановлювати Maven не потрібно.

### Збірка та тестування

Для компіляції проєкту та запуску всіх unit-тестів:

Для Windows:
```
mvnw.cmd clean test
```
Для Linux/macOS:
```
./mvnw clean test
```

Для створення .jar-файлу:

Для Windows:
```
mvnw.cmd clean package
```
Для Linux/macOS:
```
./mvnw clean package
```

## Запуск програми

Програму можна запустити через метод main у класі Main.

Інтерактивний запуск

Якщо аргументи командного рядка не передані, програма працює в інтерактивному режимі та запитує необхідні параметри через консоль:

* шлях до папки з JSON-файлами;
* атрибут, за яким потрібно сформувати статистику;
* кількість потоків.

Запуск через параметри командного рядка

Програма також підтримує передачу параметрів під час запуску.

Для Windows:
```
java -cp "target\classes;..." org.example.Main <шлях_до_папки> <атрибут> <кількість_потоків>
```
Для Linux/macOS:
```
java -cp "target/classes:..." org.example.Main <шлях_до_папки> <атрибут> <кількість_потоків>
```

Наприклад:
```
java -cp "target\classes;..." org.example.Main data tags 4
```
де:
- data - шлях до папки з JSON-файлами;
- tags - атрибут, за яким формується статистика;
- 4 - кількість потоків.


Результатм роботи буде XML-файл із назвою:

```
statistics_by_{attribute}.xml
```

Наприклад, при формуванні статистики за атрибутом tags буде створено файл:

```
statistics_by_tags.xml
```

## Бібліотеки / Залежності

Додатково встановлювати залежності вручну не потрібно. Вони визначені в pom.xml.

* Jackson - потоковий парсинг JSON-файлів.
* JUnit 5 - unit-тестування.

## Структура проєкту

### Java (main)

* Main.java - точка входу в програму. 
* PurchaseRecord.java - основна сутність предметної області. Містить інформацію про конкретний запис (операцію) закупівлі.
* Material.java - другорядна сутність. Один запис про закупівлю пов'язаний з одним матеріалом, а один матеріал може зустрічатися в багатьох записах.
* Status.java - перелік можливих статусів запису заявки.
* Unit.java - перелік одиниць вимірювання кількості матеріалу.
* JsonStreamParser.java - потоковий парсинг JSON-файлів без завантаження всього файлу в оперативну пам'ять.
* DirectoryProcessor.java - обробка JSON-файлів із директорії та організація їх паралельного опрацювання за допомогою пулу потоків.
* StatisticsAggregator.java - формування статистики за вибраним атрибутом.
* XmlReportWriter.java - формування XML-звіту зі статистикою.
* DataGenerator.java - генерація тестових JSON-файлів для проведення експериментів із продуктивністю.

### Java (test)

Unit-тести перевіряють основну логіку проєкту:

* JsonStreamParserTest - перевірка коректного потокового парсингу JSON та обробки некоректної структури.
* StatisticsAggregatorTest - перевірка формування статистики за різними атрибутами, зокрема tags, 
status, unit та material, а також обробки null, порожніх значень і невідомого атрибуту.
* XmlReportWriterTest - перевірка створення XML-файлу, його вмісту та сортування результатів.
* DirectoryProcessorTest - перевірка обробки директорій, відсутніх JSON-файлів та помилкових ситуацій.

## Файли

### JSON

Вхідні файли містять масив об'єктів основної сутності PurchaseRecord.

Приклад:

```json
[
  {
    "id": 1,
    "material": {
      "id": 101,
      "name": "Steel",
      "unit": "KG"
    },
    "quantity": 150.5,
    "status": "APPROVED",
    "tags": "urgent, metal, heavy"
  },
  {
    "id": 2,
    "material": {
      "id": 102,
      "name": "Aluminium",
      "unit": "KG"
    },
    "quantity": 80.0,
    "status": "PENDING",
    "tags": "metal, heavy"
  }
]
```

Атрибути, за якими можна формувати статистику:

* tags
* status
* unit
* material

Атрибут tags є текстовим і може містити декілька значень, розділених комами.

### XML

Результатом роботи програми є файл:

```
statistics_by_{attribute}.xml
```

Елементи сортуються за кількістю згадувань у всіх JSON-файлах у порядку спадання.

Якщо кількість однакова, додатково використовується сортування за значенням атрибуту в алфавітному порядку.

Приклад:

```xml
<statistics>
  <item>
    <value>heavy</value>
    <count>2</count>
  </item>
  <item>
    <value>metal</value>
    <count>2</count>
  </item>
  <item>
    <value>urgent</value>
    <count>1</count>
  </item>
</statistics>
```

## Тестування

Для перевірки коректності роботи програми створено unit-тести для основних компонентів системи.

Тести перевіряють:

* коректність потокового парсингу JSON-файлів;
* формування статистики за різними атрибутами;
* обробку багатозначного атрибуту tags;
* обробку null та порожніх значень;
* формування XML-звіту;
* сортування результатів;
* роботу з директоріями;
* обробку помилкових ситуацій.

Усі unit-тести успішно проходять.

### Результати тестування 

Експеримент проводився на однаковому наборі тестових даних:
10 JSON-файлів по 10 000 записів у кожному (100 000 записів загалом).
Для всіх запусків використовувався атрибут tags.
Кожна конфігурація з кількістю потоків (1, 2, 4 та 8) запускалася 10 разів. 
Як результуюче значення використовувалася медіана часу виконання.

При використанні 1 потоку медіанний час виконання склав 484 ms;

При використанні 2 потоків медіанний час виконання склав 446 ms;

При використанні 4 потоків медіанний час виконання склав 425 ms;

При використанні 8 потоків медіанний час виконання склав 403 ms.

Таким чином, зі збільшенням кількості потоків час виконання зменшується. 
Найкращий результат серед перевірених конфігурацій отримано при використанні 8 потоків - 403 ms. 
Порівняно з однопотоковим виконанням час зменшився на 81 ms, що становить приблизно 16,7%.


## Ефективність

Для парсингу JSON-файлів використовується JsonParser з Jackson Streaming API.

Кожен JSON-файл обробляється окремою задачею в пулі потоків.
Усередині кожного файлу об'єкти читаються послідовно,
об'єкт за об'єктом, за допомогою Jackson Streaming API.
Тому весь JSON-файл не завантажується в оперативну пам'ять.
Для паралельної обробки файлів використовується пул потоків.
Кожен JSON-файл передається в окрему задачу, а максимальна кількість одночасно працюючих потоків визначається параметром запуску.
