# Система агрегації статистики за закупівлями (Java Core)

Консольна багатопотокова програма на Java для потокового парсингу JSON-файлів із купівельними заявками, обчислення статистики за вказаним атрибутом та генерації відсортованого XML-звіту.

---

## 1. Опис основних сутностей

Проєкт побудований на принципах об'єктно-орієнтованого програмування та демонструє зв'язок між сутностями:

* **PurchaseRequisition (Заявка на закупівлю)** - основна сутність, що містить інформацію про закупівлю. Поля: `id` (Long), `material` (`Material` - вкладений об'єкт), `quantity` (Double), `status` (`Status` - Enum: DRAFT, IN_APPROVAL, APPROVED, CANCELED), `tags` (String - текстові теги через кому).

* **Material (Матеріал)** - другорядна сутність. Поля: `id` (Long), `name` (String), `unit` (`Unit` - Enum: KG, PCS, METERS, LITERS), `description` (String).

> **Зв'язок між сутностями:** Many-to-One - багато заявок на закупівлю можуть бути пов'язані з одним матеріалом.

Для спрощення предметної області в межах даного завдання кожна заявка розглядається як заявка на один конкретний матеріал. Один і той самий матеріал може бути вказаний у багатьох заявках.

## 2. Приклад вхідного JSON-файлу

```json
[
  {
    "id": 100001,
    "material": {
      "id": 240,
      "name": "Material_66",
      "unit": "METERS"
    },
    "quantity": 69.5,
    "status": "IN_APPROVAL",
    "tags": "heavy, wood"
  }
]

```

---

## 3. Приклад вихідного XML-файлу

```xml
<?xml version="1.0" encoding="UTF-8"?>
<statistics>
  <item>
    <value>heavy</value>
    <count>1</count>
  </item>
  <item>
    <value>wood</value>
    <count>1</count>
  </item>
</statistics>

```

## 7. Запуск програми

Програма підтримує два способи запуску:

1. Інтерактивний запуск через консоль.
2. Запуск із параметрами командного рядка.

* **При інтерактивному запуску** користувач вводить: шлях до папки з JSON-файлами, назву атрибута та кількість потоків.
* **При запуску з параметрами:**
```bash
<шлях_до_папки> <атрибут> <кількість_потоків>

```


*Приклад:* `data tags 4`

## 8. Потокова обробка JSON-файлів

Для парсингу використовується Jackson Streaming API. JSON-файли обробляються по одному об'єкту без завантаження всього файлу в оперативну пам'ять.

---

## 9. Багатопотокова обробка

Для обробки файлів використовується `ExecutorService` з фіксованим пулом потоків. Кожен JSON-файл передається на обробку окремому потоку.

Для безпечної роботи зі статистикою в багатопотоковому режимі використовуються `ConcurrentHashMap` та `LongAdder`.

---

## 10. Результати експериментів

Для порівняння швидкодії програма була запущена з різною кількістю потоків:

| Кількість потоків | Час виконання |
| --- | --- |
| **1** | 515 ms |
| **2** | 461 ms |
| **4** | 419 ms |
| **8** | 410 ms |

> Зі збільшенням кількості потоків час виконання зменшується. Найбільше прискорення спостерігається при переході від 1 до 4 потоків. При використанні 8 потоків покращення порівняно з 4 потоками є незначним.

## 11. Unit-тести

Для перевірки основної логіки проєкту реалізовані unit-тести:

* **`JsonStreamParserTest`** - перевірка парсингу JSON-файлів;
* **`StatisticsAggregatorTest`** - перевірка формування статистики та обробки багатозначних атрибутів;
* **`DirectoryProcessorTest`** - перевірка обробки директорії та генерації XML-звіту;
* **`XmlReportWriterTest`** - перевірка формування XML-файлу.
